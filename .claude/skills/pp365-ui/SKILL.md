# UI in PP365 (React 17, Fluent UI v9)

Authoritative (Norwegian): `.development-guide/spfx/kodemonster.md`. This skill is the operational summary, the inventory of shared wrappers the guide lacks, and the traps recorded in `docs/plans/fluent-v9-migration.md` and `docs/plans/fluent-v9-phase-4.md`.

## Read first

- `kodemonster.md`, all of it: folder and barrel, hook, context, reducer, loc, SCSS modules, Fluent v9, icons, PnP controls, slot render functions. Beside it in `.development-guide/spfx/`: `komponentoversikt.md` maps web parts and extensions to solutions, `utviklingsmiljo.md` covers watching and debugging, `testing.md` the tests.
- The closest existing component in the same solution, and the wrapper table below, before writing anything new.
- Where kodemonster.md or AGENTS.md disagree with the code, follow the code and fix the guide.
- Stack: React 17.0.1 (no `React.useId`, no `createRoot`), `@fluentui/react-components` ~9.74.8, `@fluentui/react-icons` ~2.0.341, `@reduxjs/toolkit` ~2.13.0. Fluent v8 (`@fluentui/react`) remains only as the Fabric font fallback in `shared-library/src/icons/index.tsx`.

## Component shape

- Follow kodemonster.md's folder: `index.ts` re-exports only, `X.tsx` JSX only (`export const X: FC<IXProps>`), `export function useX` holding state, effects and handlers, `types.ts`, `X.module.scss`, `context.ts`/`reducer.ts` when needed. JSDoc on exported symbols.
- About 65 component folders still keep the component in `index.tsx` (`UserMessage`, `WebPartTitle`, `OverflowTagMenu`, `ProjectLogo` in the library), and some hooks are arrow constants. Some call sites below are such files: copy the call, not the shape, and restructure one only when that is the task.
- Reducers: `createReducer` with the builder callback (`builder.addCase(ACTION, (state, { payload }) => …)`), as all nine are; Redux Toolkit 2 removed the object notation. Type a context's `dispatch` as `React.Dispatch<UnknownAction>`. Every handler has a test in the `reducer.test.ts` beside it (`ProgramWebParts/src/components/ProgramAdministration/reducer.test.ts`).
- Ids: `useId` from `@fluentui/react-components` in components and hooks; `getId(prefix)` from `pp365-shared-library` only outside React (module scope, class fields).
- A web part's class is `src/webparts/<name>/index.ts(x)` on the solution's base web part (`this.renderComponent(Component, props)`); its UI is `src/components/<Name>`.
- Consumers import their own folders bare (`components/X`, `models`, `data`; `baseUrl: src`). A new bare-imported folder goes into the solution's `tsconfig.json` `paths`: webpack's aliases come only from there (`config/spfx-customize-webpack.js`), while TypeScript and Jest resolve any folder, so it compiles and passes its tests, then fails to bundle.
- Import the library from `pp365-shared-library` (deep `pp365-shared-library/lib/...` paths also work); inside `shared-library` imports are relative (`../../util`).
- A new shared wrapper: a folder under `shared-library/src/components`, a line in `components/index.ts`, its texts in the `SharedLibraryStrings` triad. The library has no `watch`: run `rush rebuild -o pp365-shared-library` (or `npx heft build --clean` in it) before a consumer sees any library change.

## Icons (`shared-library/src/icons`)

- `getFluentIcon(name, { color, size, filled, bundle, jsx, className })`: `name` is a catalog name (`FluentIconName`, the keys of `iconCatalog.ts`; `getFluentIcons()` lists them). It reads the catalog only and returns `null` for a UI Fabric alias. Bundled icons are cached per name; `jsx: false` returns the component. Catalog icons are mostly unsized (1em): pass `size`, or beside sized siblings bundle the `*24` pair once at module scope.
- `getFluentIconWithFallback(name, { color, size, filled, className })` for names from list data or configuration (`GtSecIcon` and friends): catalog, then `fabricIconAliases.ts`, then the Fabric font; `null` for an empty name (`ProjectWebParts/src/components/ProjectStatus/StatusElement/StatusElementIcon/StatusElementIcon.tsx`). The boolean-argument form is deprecated.
- `getIconComponentWithFallback(name, 'Cube')` where a prop wants a component (`Tab`, `MenuItem`): `PortfolioWebParts/src/components/ProjectList/ProjectListFilterRegistry.ts`. It, `getFluentIconWithFallback` and `isIconAvailable` resolve aliases through `resolveFluentIcon`.
- `ListMenuItem.setIcon` takes a name string, resolved like `getFluentIconWithFallback` (`Toolbar/createIcon.tsx`; `setIcon('Filter')` in `PortfolioWebParts/src/components/PortfolioOverview/ToolbarItems/useToolbarItems.ts`), or a component (`getFluentIcon(name, { jsx: false })`, a module-scope `bundleIcon`).
- A new icon: "Legge til et ikon i katalogen" in kodemonster.md, then rebuild the library.

## Typical tasks

- **Extend an existing component** through its own action list, panel union and reducer before reaching for a wrapper. Project information: `ActionType` tuples in `ProjectWebParts/src/components/ProjectInformation/Actions/useActions.ts` (a new `actionsMap` key also goes into the `hideActions` options in `webparts/projectInformation/index.ts`); a panel is a `ProjectInformationPanelType` member opened with `OPEN_PANEL`, closed with `CLOSE_PANEL`.
- **Panel**: `BasePanel`, or `CustomEditPanel` for an item form; save and cancel in `footer`, actions instead of a title in `header`. Open state lives in the component's reducer when it has one, otherwise in `useState` in its hook. Put no provider inside: `EditViewColumnsPanel`, both `ViewFormPanel`s, both `ColumnFormPanel`s and `NewRiskActionPanel` still nest one; do not copy them.
- **Dialog**: v9 `Dialog` (`DialogSurface` > `DialogBody` > `DialogTitle`, `DialogContent`, `DialogActions`). Model: `shared-library/src/components/ItemColumn/DialogColumn/index.tsx`, with a dismiss button in `DialogTitle`'s `action` (`aria-label={strings.CloseText}`) and a "Lukk" button in `DialogActions`, each in `DialogTrigger action='close'`. Under an existing provider (a cell, a panel) a dialog needs none; in its own React root it gets `IdPrefixProvider value={useId('fp-…')}` + `FluentProvider theme={customLightTheme}`, as `useConfirmationDialog` does. A yes/no question is `useConfirmationDialog` itself.
- **Form field**: each control in a `FieldContainer`, texts from the strings module; accessibility rules below. A date picker is `DatePicker` from `@fluentui/react-datepicker-compat`, declared only in shared-library and ProjectWebParts: elsewhere add the dependency (pp365-toolchain) or use `Input type='date'` as `NewRiskActionPanel` does.
- **List**: `DataGridList` with `IDataGridColumn` (`createTableColumn` plus `minWidth`/`defaultWidth`) or `createDataGridColumns(IListColumn[])`, which returns `{ columns, columnSizingOptions }`: pass `.columns`, memoized on the source columns (`ProjectWebParts/src/components/ProjectStatus/Sections/ListSection/ListSection.tsx`). A changed set of column ids remounts the grid and resets sort and sizing, so never build columns afresh per render, least of all with `getId` keys.
- Not `DataGrid` directly: the wrapper carries the 12px `--colorNeutralForeground3` typography, an `overflow-x: auto` container, the selection-cell labels and a fit that allows for Fluent's 44px selection cell and 16px column padding.
- Two lists are not `DataGridList`: the hub (`PortfolioWebParts/src/components/List`, Fluent `Table` in `List/ListGrid`, for groups, a pinned header and shift-click ranges; a new cell type there is a registered `ColumnRenderComponent`) and the dynamic list's table view (`ProjectWebParts/src/components/DynamicList/views/ListView/ListView.tsx`, `Table` with `useTableFeatures`).
- **Toolbar command**: a `ListMenuItem` built in the component's hook. An icon-only item has `null` text and a `description`, which becomes its `title` and `aria-label`. A checkable item needs `makeCheckable({ name, value })` and its parent `setItems(items, checkedValues)` (the render-mode menu in `useCommands.tsx`).
- **Column header menu** (portfolio overview, aggregation, dynamic list): not `ListMenuItem` but `IMenuItem` (`shared-library/src/types/MenuItem.ts`: `canCheck`, `checked`, `data: { name, value }`, `subMenuProps`, `iconProps.iconName`), built in each `ColumnContextMenu/useColumnContextMenu.ts`, which also holds `checkedValues`, and rendered by `PortfolioWebParts/src/components/List/ColumnContextMenu/renderMenuItem.tsx` (the dynamic list has its own copy in `DynamicList/components/ColumnContextMenu`).
- In those menus a checkable item without `data.name` and `value` never shows its check (the group-by item until phase 4); `iconName` must be a catalog name, since `renderMenuItem` uses `getFluentIcon`; a submenu's trigger drops the close handler and is marked `hasSubmenu`.
- **Notice after an action**: no wrapper; Fluent's `<Toaster toasterId={toasterId} />` with `useId('toaster')` and `useToastController(toasterId).dispatchToast(<Toast>…</Toast>, { intent })`, as `ProgramWebParts/src/components/ProgramAdministration/Commands/Commands.tsx`. A toast confirms what just happened; a `UserMessage` states a lasting condition in place (error, empty, info).
- **Styling**: `import styles from './X.module.scss'`, `className={styles.x}`, selectors nested as the DOM. Colours, sizes and weights from Fluent's tokens (`var(--colorNeutralForeground3)`, `var(--fontSizeBase200)`, `var(--fontWeightSemibold)`), which exist only under a `FluentProvider`; the v8-to-token table heads `ProjectExtensions/src/components/ProgressDialog/ProgressDialog.module.scss`.
- To restyle a Fluent part, nest `:global(.fui-…)` under your module class, which outranks Fluent's single-class rules whatever the injection order (`DataGridList.module.scss`). Read Fluent's own styles rather than guess: its sub-packages are only in the pnpm store, `common/temp/node_modules/.pnpm/@fluentui+<pkg>@<version>_*/node_modules/@fluentui/<pkg>/lib`.
- **See it in the browser** (`utviklingsmiljo.md`): `npm run watch` in the solution. It bundles `shared-library` and `ProjectWebParts` from their `lib/` as they are, so build those first (`rush build -T <package>`, or `npx heft build --clean` in each). `SERVE_CHANNEL` in the solution's `.env` must match the page's channel (the test hub is on `test`) or the page never asks for your bundles; `SERVE_BUNDLE_REGEX` narrows the build.
- To debug from VS Code with the repo open: copy `.vscode/launch.sample.json` to `.vscode/launch.json`, `npx heft trust-dev-cert` once in a solution, run `npm run watch`, then start "Debug a page against npm run watch" (F5) on the page, without a query string.
- **Test**: a component test next to the component (pp365-testing has the stand-ins for Fluent's combobox family and popovers, and the workarounds for menus and drawers). Mock the hook or adapter that fetches; a hook that only reads context is covered by rendering with a context stand-in value (`ProjectInformation/Actions/Actions.test.tsx`). Strings resolve to nb-no, so `BasePanel`'s close button is "Lukk". Coverage floors in each `config/jest.config.json`: `heft test` only reports a missed floor, `Install/Build-Release.ps1` fails on it.
- **Changelog**: a user-visible change gets a Norwegian line in `CHANGELOG.md` under the coming version (`Ny funksjonalitet`, `Forbedringer` or `Feilrettinger`).

## Fluent v9 pitfalls

- **One provider per surface root.** Each `FluentProvider` injects a `<style>` with the whole theme into `document.head`, so never one per cell or row: cells render under the list's provider (`PortfolioWebParts/src/components/List/List.tsx`). Wrappers with own providers need none around or inside them. A provider paints `colorNeutralBackground1` and body typography, hence `Fluent transparent`. A surface in its own React root (an extension's dialog) needs its own.
- Keep `applyStylesToPortals` at its default and drawers modal (comments in `BasePanel.tsx`): with the flag off a portalled drawer gets no theme and renders invisible; a `non-modal` drawer renders inline, behind the web part.
- **Portalled clicks bubble through React.** A dialog, popover or menu that a row's cell opens is portalled elsewhere in the page, yet React passes its clicks up through the row. A clickable row ignores clicks that did not land inside it in the DOM: `isOwnClick` in `PortfolioWebParts/src/components/List/ListGrid/ListGrid.tsx` (`event.currentTarget.contains(event.target)`, and not on a link, button or check of its own).
- **Hover popovers in cells** (`PortfolioWebParts/src/components/List/ItemColumn/StatusReportColumn`): `openOnHover` opens with no delay, and the surface paints at the viewport's top left until positioning stamps `data-popper-placement`. Control `open` with a timer (`openDelay` 500), cancel it in the trigger's `onPointerLeave` (Fluent reports the leave only after `mouseLeaveDelay`, 500 ms by default, 200 there), and hide the surface with `&:not([data-popper-placement]) { visibility: hidden }`.
- **Tooltips in rows**: once one tooltip under a provider is visible, the next opens with no delay, and `relationship='description'` (or `label` with non-string content) keeps a hidden portal per instance. In rows use a native `title`, or `relationship='label'` with a string (`shared-library/src/components/ItemColumn/UserColumn`).
- `bundleIcon()` returns a new component type per call; in a render or hook body it remounts the icon on every render. Call it at module scope (`PortfolioWebParts/src/components/IdeaModule/IdeaModule.tsx`) or use `getFluentIcon`; `ProjectCardFooter/useProjectCardFooter.ts`, `ProjectInformation/Actions/useActions.ts` and `ProjectStatus/Commands/useToolbarItems.tsx` still do it per render. A component declared inside a render body churns the same way.
- **Truncating text in a Fluent `Button`**: Fluent's reset gives the button `resize: horizontal`, which draws a browser grip once `overflow` is hidden. Give it `min-width: 0; overflow: hidden; resize: none`, and the text its own span with `white-space: nowrap; text-overflow: ellipsis` and a `title` (`.headerButton` in `List/ListGrid/ListGrid.module.scss`).
- Memo and effect dependencies: the `Fluent` wrapper once memoized its tree with no dependencies and froze the status page on its first render; a fresh `[]` default on every render re-ran an effect on every render (project information's child projects).
- No entrance animation that keeps its end state (`forwards`/`both`) on list rows: in Chrome/Edge on a Retina Mac such rows stay on their own compositor layers and paint as white tiles (the 1.14.0 fix "hvite, flimrende felter" in `CHANGELOG.md`); DevTools' Layers panel names the cause.
- Shipping in `@fluentui/react-components` does not prove a control works on React 17, and failing under jsdom does not prove it broken: the combobox family and `Menu` hang under jsdom yet work in the browser. Try a new kind of control in a browser first (pp365-testing).
- **Renaming a prop**: props objects (`useMemo<IXProps>`, `: IXProps =`, `as IXProps`) that are spread skip excess-property checks; that is how five panels kept `isOpen` and never opened (`docs/plans/fluent-v9-migration.md`). `IBasePanelProps` declares `isOpen`/`onDismiss` as `never` for that reason; grep for the objects.
- **A fix that does nothing**: first prove the browser runs your bundle (a visible tell, or the bundle URL in the Network tab): the right solution watched, its dependencies built, and after a deployment SharePoint can serve a component's previous manifest for minutes. A `<style>` tag added from the console tests CSS without a build.

## Accessibility of form fields

- In a `FieldContainer` a v9 control takes the field's id, so the label names it and a click on the label reaches it; check `for` against `id` in the browser.
- A slot render function must pass on what Fluent wired (kodemonster.md, "Render-funksjoner for slots"): `FieldContainer/IconLabel/IconLabel.tsx` puts `labelProps.id` and `htmlFor` on its `Label`.
- A control that ignores the field gets its props through `useFieldControlProps_unstable(props, { supportsLabelFor: true })`, as `FieldDatePicker` in `FieldElements/DateTime.tsx` does for the compat `DatePicker`.
- `PeoplePicker` takes the field's label inside a `Field`; outside one pass `aria-label`. PnP's `ModernTaxonomyPicker` takes no input props, so its label stays apart.
- Icon-only buttons get an `aria-label` from the strings (`BasePanel`'s close button: `strings.CloseText`). `DataGridList` labels its selection checks (`DataGridSelectAllLabel`, `DataGridSelectRowLabel`), the hub its own (`ListSelectRowLabel`, `ListSelectGroupLabel`).

## Localized strings

- Components use their solution's module: `import strings from 'ProjectWebPartsStrings'` (or `import * as strings`; both compile, match the file). The library uses `SharedLibraryStrings`; consumers never import it.
- `SharedResources` (`import resource from 'SharedResources'`) holds the names and texts the templates provision; label a field with `resource.SiteFields_<Name>_DisplayName` rather than a new key. It is generated into each solution's `src/loc/shared` from `Templates/Portfolio/Resources.*.resx` by `npm run generate-resx-ts` in `Templates`.
- A new key goes into the declaration file, `nb-no.js` and `en-us.js`, phrased like its siblings in both languages; groups such as `strings.Aria.*` are fine. Interpolate with `format`, never concatenation; `Error()` texts the UI shows are strings too.
- A key missing from one bundle is `undefined` in that language: text renders nothing and `format()` throws. `,,` in a bundle is a syntax error that takes the whole bundle down (in `nb-no.js` it also fails the Jest run).
- `npm run validate-loc` (all solutions: `rush validate-loc`) writes the interface keys missing from each bundle to `localization-report.md` (gitignored) and logs `N missing keys in <lng>`. It exits 0 even then, cannot see a key that exists only in a `.js` file, and is part of neither `npm run build` nor CI: read its output.

## Do not

- Import `@fluentui/react` (v8) in new code.
- `import * as` from `@fluentui/react-icons`, deep-import `pp365-shared-library/lib/icons/iconCatalog`, or import a PnP control from its package root (`@pnp/spfx-controls-react`, `@pnp/spfx-property-controls`); ESLint stops all three (`SharePointFramework/.eslint-config/index.js`).
- Put logic or JSX in a barrel, or edit `temp/sass-ts` or `src/loc/shared` by hand.
- Use `isOpen`/`onDismiss` on `BasePanel`, a `non-modal` drawer, or `applyStylesToPortals={false}`.
- Add a provider around or inside a wrapper that has its own, or one per cell or row; call `bundleIcon` in a render; animate list rows in.
- Render Fluent's `DataGrid` directly for a new list, or rebuild a list's columns on every render.
- Style with Griffel `makeStyles` outside the two components that already do (`TemplatePackageCatalog`, `ProjectMenu`); use `.module.scss`.
- Hard-code user-facing text in either language, error messages and `aria-label`s included.
- Remove a `fabricIconAliases.ts` entry; tenants keep the old names in their lists for good.
- Take `npx tsc --noEmit` as the check: it runs no ESLint, and the error-level rules (`unused-imports/no-unused-imports`, `react/jsx-key`, `prettier/prettier`, the restricted imports) fail `heft build`; run `npx eslint <files>` in the solution.
